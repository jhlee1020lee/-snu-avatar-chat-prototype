# 처음 플레이어 친절도 회의 보고서

- 작성일: 2026-06-03
- 대상 빌드/폴더: `Interviewee1UnityAvatarChat`
- 회의 성격: 실제 외부 참가자 회의가 아니라, 현재 코드, 자동 스모크 결과, 기존 플레이테스트 문서를 근거로 진행한 내부 역할별 리뷰 회의
- 핵심 질문: 처음 하는 사람이 `겉!=속`을 보고 1분 안에 무엇을 해야 하는지, 왜 그 행동을 해야 하는지, 어디까지 하면 한 세션인지 이해하는가?

## 결론

현재 빌드는 이전보다 시각적으로 정돈됐고 추천 질문 카드도 더 명확해졌지만, 처음 하는 사람에게는 여전히 "무슨 게임인지"보다 "버튼을 눌러야 하는 화면"으로 먼저 읽힐 위험이 크다. 가장 큰 문제는 조작법 설명 부족이 아니라, 첫 1분 안에 플레이어가 자기 행동의 의미를 이해하도록 이어 주는 온보딩 문장이 부족하다는 점이다.

회의 결론은 다음과 같다.

1. 첫 화면은 `시작 버튼`만 더 잘 보이게 하는 문제가 아니라, "오늘 할 일은 5번 질문해서 겉 단서가 생활 장면으로 이어지는지 확인하는 것"을 먼저 알려야 한다.
2. 첫인상 3지선다는 유지할 수 있지만, 선택 전에 "이 선택이 이후 질문을 여는 관찰 시작점"이라는 설명이 더 구체적이어야 한다.
3. 추천 질문 카드는 현재 스모크상 겹치지 않지만, 처음 플레이어에게는 "정답 후보"처럼 보일 수 있으므로 "고르면 질문을 보내는 카드"와 "직접 질문해도 됨"을 같은 화면에서 알려야 한다.
4. 질문 노트는 기능적으로 충분하지만 `장면`, `깊은 기록`, `더 묻기` 같은 내부 진행어가 초반에는 추상적이다. 첫 세션에서는 생활 장면을 여는 말로 번역해야 한다.
5. 외부 플레이테스트 관찰 양식은 첫 1분 기록 항목이 있으나, 이번 이슈를 잡기에는 "목표 이해", "첫 선택 의미 이해", "5문답 구조 이해" 항목이 더 필요하다.

## 회의록

### 기획 관점

처음 플레이어가 이해해야 하는 것은 조작 순서가 아니라 질문의 목적이다. 현재 화면은 "장면을 고르고 질문한다"는 동작은 제공하지만, "겉으로 보이는 단서에서 출발해 속의 생활을 확인한다"는 목표가 첫 행동 전에 충분히 박히지 않는다.

결정:

- 첫 화면 목적 문장을 1문장 목표 + 1문장 행동으로 분리한다.
- `5문답` 구조를 시작 전부터 숨기지 않는다. 플레이어가 언제 끝나는지 알아야 부담이 줄어든다.
- 첫인상 선택지는 정답이 아니라 "첫 관찰점"이라는 표현을 더 강하게 쓴다.

### UX 관점

첫 화면, 첫인상 선택, 추천 질문, 질문 노트가 각각 다른 방식으로 "질문하라"고 말한다. 초보자에게는 이것이 다양한 선택지가 아니라 여러 시스템이 동시에 말하는 느낌이 될 수 있다.

결정:

- 첫 세션 첫 1분은 하나의 선형 안내로 잡는다: `짧은 이야기 보기 -> 먼저 보인 단서 고르기 -> 추천 질문 하나 누르기 또는 직접 질문`.
- 추천 질문 카드에는 이미 "누르면 바로 질문"이 들어갔으므로, 주변 안내는 "직접 써도 됩니다"를 보완한다.
- 질문 노트의 초반 문구는 진행 상태보다 다음 행동을 먼저 말한다.

### QA 관점

자동 스모크는 카드 겹침, 버튼 표시, 진행 상태를 확인하지만, "처음 하는 사람이 이해했는가"는 아직 증명하지 못한다. 기존 플레이테스트 양식은 충분한 출발점이지만 이번 이슈를 재현하려면 첫 1분 관찰이 더 세분화되어야 한다.

결정:

- 플레이테스트 관찰 양식에 다음 항목을 추가해야 한다.
  - 시작 화면에서 게임 목표를 자기 말로 설명했다.
  - 첫인상 선택이 정답 선택이 아니라 관찰 시작점임을 이해했다.
  - 추천 질문 카드가 실제 질문 전송 버튼임을 이해했다.
  - 직접 질문이 가능하다는 것을 알았다.
  - 5문답 후 마무리로 간다는 구조를 이해했다.

### 개발 관점

큰 구조를 다시 만들지 않아도 첫 진입 친절도는 텍스트와 흐름의 우선순위 조정만으로 개선할 수 있다. 다만 시작 화면 카드와 첫인상 모달의 문장 길이가 늘어나면 버튼 위치, 줄바꿈, 모바일/배율 환경에서 겹침 검사가 필요하다.

결정:

- 1차 수정은 코드 구조 변경보다 카피와 상태 안내 개선으로 진행한다.
- 수정 후 `ValidateCommercialUiCopy.ps1`, `ValidateAccessibilityAutomation.ps1 -StaticOnly`, 시작/첫인상/추천질문 스모크를 다시 만든다.
- 실제 플레이어 3명 이상에게 "설명 없이 첫 질문까지" 테스트를 먼저 돌린 뒤, 5명 완성 세션으로 확대한다.

## 바로 적용할 문구안

### 시작 화면

현재:

> 짧은 이야기를 먼저 듣고, 방금 본 장면에서 질문을 시작합니다.

제안:

> 목표: 먼저 보인 단서가 한 사람의 생활과 어떻게 이어지는지 5번 질문해 봅니다.
> 시작: 짧은 이야기를 듣고, 가장 먼저 보인 장면 하나를 고르세요.

### 첫인상 선택

현재:

> 방금 본 이야기에서 무엇이 먼저 들어왔나요? 겉 단서를 고르면, 연결된 속 장면에서 질문을 시작합니다.

제안:

> 정답을 고르는 화면이 아닙니다. 가장 먼저 보인 단서를 고르면, 그 단서에서 첫 질문이 열립니다.

버튼 보조 라벨:

- `목발` -> `이동과 도움을 물어보기`
- `책상` -> `일과 공부를 물어보기`
- `표정` -> `평범한 하루를 물어보기`

### 기본 대화 화면

제안 안내:

> 추천 질문을 눌러 바로 물어보거나, 아래 입력칸에 직접 질문해도 됩니다. 5번 질문하면 남길 문장을 정리합니다.

### 질문 노트

현재 초반 상태:

> 장면: 새로 열기 6 · 더 묻기 0 · 깊음 0 · 배려/호기심으로 깊게

제안:

> 아직 열린 생활 장면이 없습니다. 궁금한 장면을 골라 첫 질문을 시작하세요.

## 다음 작업 제안

### 1차 수정

- 시작 화면 목적 문구를 목표/시작/완료 조건으로 재작성한다.
- 첫인상 모달 문구를 "정답 아님"에서 한 단계 더 나아가 "선택 후 첫 질문이 열린다"로 바꾼다.
- 첫인상 버튼 보조 라벨을 행동형으로 바꾼다.
- 질문 노트 초반 가이드 문구를 내부 진행어가 아니라 플레이어 행동 문장으로 바꾼다.

완료 기준:

- 처음 화면 스모크 리포트에 목표 문장과 5문답 조건이 기록된다.
- 첫인상 스모크 리포트에 새 프롬프트와 버튼 라벨이 기록된다.
- 추천 질문 카드 겹침 검사 `PASS` 유지.

### 2차 검증

- 설명 없이 플레이어 3명에게 첫 질문까지 진행시킨다.
- 기준은 "첫 질문까지 90초 이하", "목표 설명 성공 2/3 이상", "첫인상 선택 의미 이해 2/3 이상"이다.
- 실패하면 UI 구조 수정으로 넘어간다. 예: 시작 화면에 3단계 진행 바, 첫인상 선택 전 예시 질문 1개, 직접 입력 CTA 강조.

### 3차 외부 테스트

- 기존 외부 플레이테스트 패키지로 5명 이상 5문답 세션을 수집한다.
- 이번 보고서의 추가 관찰 항목을 세션 양식에 반영한다.
- P0/P1 이슈가 나오면 상업 출시 판단보다 온보딩 수정 스프린트를 우선한다.

## 최종 판단

처음 하는 사람에게 불친절하다는 지적은 타당하다. 최근 수정으로 추천 질문 카드 자체는 명확해졌지만, 첫 진입에서 "무엇을 왜 하는지"를 잡아 주는 구조는 아직 충분히 증명되지 않았다. 다음 수정은 새 기능 추가보다 첫 1분의 언어를 정리하는 것이 우선이다. 목표, 첫 선택의 의미, 질문 방법, 완료 조건을 한 화면 흐름으로 연결하면 같은 게임 구조를 유지하면서도 초보자 이탈을 줄일 수 있다.
