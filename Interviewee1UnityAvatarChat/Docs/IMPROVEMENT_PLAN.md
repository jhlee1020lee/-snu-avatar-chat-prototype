# 대상자1 아바타 인터뷰 개선 기획서

작성일: 2026-05-21

## 목표

관람자가 개발 설명을 듣는 느낌이 아니라, 책상 맞은편에 앉은 한 사람의 일상을 차분히 묻고 듣는 느낌을 받게 한다. 기존 별도 게임은 수정하지 않고, Unity 아바타 인터뷰 앱과 답변 서버만 개선한다.

## 핵심 문제

- 일부 답변이 관람자에게 말하기보다 전시 제작자에게 설명하는 문장처럼 들렸다.
- 긴 답변이 화면 아래로 밀려 내려가 읽기 어려웠다.
- 캐릭터가 좌우로 눌려 보이고, 보라색 경계선이 남아 있었다.
- 배경과 패널이 어두워 인터뷰보다 조사실처럼 보였다.
- 입력 직후의 대기 문장이 길고 AI 시스템 문구처럼 느껴졌다.
- 답변 첫머리의 정체성 고지, 별표 강조, 보고서 말투가 몰입을 깨뜨렸다.

## 참고한 유사 사례

- Coffee Talk: 장면과 인물을 중심에 둔 조용한 대화 경험.
- VA-11 Hall-A: 선택지와 대화 흐름을 함께 보여주는 대화 중심 인터페이스.
- Her Story: 인터뷰 자료와 단서가 대화를 이끄는 구조.
- USC Shoah Foundation Dimensions in Testimony: 관람자가 질문하고 증언형 답변을 받는 형식.
- Kind Words: 짧고 부담 없는 문장, 과장하지 않는 위로의 톤.
- Gone Home: 물건과 생활 공간으로 한 사람을 읽게 하는 방식.
- A Normal Lost Phone: 사적인 단서가 인물 이해로 이어지는 구성.
- Before Your Eyes: 한 사람의 생애를 차분한 장면 전환으로 따라가는 흐름.
- Eliza: AI가 매개하는 상담형 대화의 긴장감과 UI 절제.

## 기획 방향

1. 답변은 전시 설명이 아니라 관람자에게 직접 들려주는 말로 쓴다.
2. 사용자가 제작 방식이나 전시 구성을 직접 묻지 않는 한 `전시`, `프로그램`, `UI`, `구성`, `보여주면 좋다` 같은 제작자용 표현을 쓰지 않는다.
3. 대기 문장은 `잠시만요. 생각 좀 해볼게요.` 정도로 짧게 둔다.
4. 답변은 보통 2~4문장으로 유지하고, 긴 글은 하단 대사창 스크롤로 읽게 한다.
5. 마크다운 강조, 제목, 목록 기호는 답변에 쓰지 않는다.
6. 정체성 고지는 첫머리에 반복하지 않고, 실제 인물인 척 새 정보를 만들지 않는다.
7. 화면은 밝은 연구실 배경, 책상 앞 캐릭터, 하단 대사창, 오른쪽 흐름 패널로 구성한다.
8. 오른쪽 패널은 대화 기록보다 다음 질문 흐름을 돕는 보조 패널로 둔다.
9. 배경 핫스팟은 긴 라벨 대신 작은 `+` 버튼으로 처리해 장면을 가리지 않는다.
10. 캐릭터는 자연스러운 비율로 보이게 하고, 보라색 배경 제거 흔적을 줄인다.

## 반영 내역

- GPT 이미지 생성기로 밝은 인터뷰룸 배경을 만들고 `Assets/Resources/Scene/interview_room_background_v2.png`로 적용했다.
- Unity 앱이 새 배경을 먼저 로드하고, 실패하면 기존 배경으로 돌아가도록 했다.
- 어두운 오른쪽 패널을 종이 느낌의 밝은 패널로 바꿨다.
- 챕터와 후속 질문 버튼의 색, 글자색, 크기를 조정해 읽기 쉽게 했다.
- 하단 대사창은 긴 답변이 화면 밖으로 빠지지 않게 내부 스크롤을 유지한다.
- 핫스팟 라벨을 작은 `+` 버튼으로 바꾸고 캐릭터 얼굴을 가리지 않게 위치를 조정했다.
- 아바타 텍스처의 보라색 크로마키 경계선을 제거하는 후처리를 강화했다.
- 답변 데이터와 서버 프롬프트에서 제작자용 표현, 보고서 말투, 마크다운 강조를 막았다.
- API 키는 코드나 문서에 저장하지 않고, 서버 실행 환경의 `OPENAI_API_KEY`만 읽도록 유지했다.
- 오른쪽 고정 패널을 제거하고, 질문 흐름을 화면 위 질문 칩과 접이식 `질문폰`으로 재배치했다.
- 질문폰은 실제 스마트폰처럼 보이도록 본체, 화면, 노치, 상태바, 홈 인디케이터, 측면 버튼을 추가했다.
- 근거와 지난 대화 탭은 기본 플레이 흐름에서 빼고, 질문 선택과 마무리 행동만 남겼다.
- 하단 대사창 오른쪽에 5문답 진행 표시를 추가해 마무리 카드가 왜 잠겨 있는지 바로 알 수 있게 했다.
- 5문답 이후 열리는 `오늘 남길 문장` 마무리 카드 오버레이를 추가해 한 번의 인터뷰 세션이 끝나는 느낌을 만들었다.
- 마무리 카드에 `오늘 열린 장면` 요약을 붙여, 질문 중 수집한 기억장 장면이 엔딩 보상으로 다시 연결되게 했다.
- 마무리 카드에서 고른 문장과 열린 장면 요약을 로컬 텍스트 기록으로 저장할 수 있게 했다.
- 판매용 게임의 기본 구조를 맞추기 위해 타이틀 시작 화면, 질문폰으로 시작하기, ESC 일시정지, 계속하기, 처음부터, 종료 흐름을 추가했다.
- 처음부터를 누르면 질문 기록, 진행도, 대사, 질문 추천, 마무리 카드 상태가 초기화되도록 세션 리셋 루프를 만들었다.
- 첫 화면과 상단 상태 문구에서 로컬 서버 주소 같은 내부 구현 정보가 보이지 않도록 사용자용 문장으로 정리했다.
- 질문 답변을 받을 때마다 `일상`, `이동`, `도움`, `일과 공부`, `독립`, `취미` 중 하나의 장면이 `기억장`에 수집되도록 했다.
- 상단에 `기억장 0/6` 버튼을 추가하고, 기억장 오버레이에서 열린 장면과 아직 듣지 못한 장면을 한눈에 볼 수 있게 했다.
- 처음부터 다시 시작하면 기억장 수집 상태도 함께 초기화되도록 했다.
- 질문을 완료할 때마다 대화 기록, 진행도, 기억장, 추천 질문, 현재 표정과 마지막 대사를 자동 저장하도록 했다.
- 타이틀 화면에 `이어하기` 버튼을 추가해 앱을 다시 켜도 이전 인터뷰 세션을 이어갈 수 있게 했다.
- `처음부터`를 선택하면 자동 저장 데이터까지 삭제해 새 세션으로 명확히 시작하게 했다.
- 긴 답변을 읽는 부담을 줄이기 위해 대사창 상단에 `가-`, `가+` 글자 크기 조절 버튼을 추가했다.
- 타이틀과 일시정지 화면에서 열 수 있는 `설정` 메뉴를 추가해 글자 크기와 화면 모드를 한곳에서 바꿀 수 있게 했다.
- 설정 메뉴에 `정보` 화면과 `기록 폴더` 버튼을 추가해 자료 기반, API 키 저장 정책, 마이크 사용 범위, 로컬 기록 위치를 앱 안에서 확인할 수 있게 했다.

## 2차 검토 회의

- 첫 화면은 기능은 갖췄지만, 중앙 패널 안에 빈 공간이 크고 시작 행동의 우선순위가 약해 판매용 첫인상이 낮아 보였다.
- `종료` 버튼은 배경과 너무 가까워 보조 행동이라도 누를 수 있는 버튼처럼 보여야 한다는 의견이 있었다.
- 설명 문장을 더 늘리면 AI 데모처럼 보일 수 있으므로, 긴 안내 대신 `묻기`, `기억장`, `남길 문장` 흐름을 짧은 칩으로 보여주기로 했다.
- 저장 이어하기가 있을 때와 없을 때 모두 `처음부터`가 명확한 시작 행동으로 보이도록 버튼 폭과 대비를 조정하기로 했다.
- 답변 데이터의 요약과 상황 문장에도 `정리됨`, `언급됨` 같은 보고서 말투가 남아 있으면 서버 답변 말투에 섞일 수 있어 함께 정리하기로 했다.

## 2차 반영 내역

- 타이틀 화면에 그림자와 `오늘의 흐름` 칩을 추가해 첫 화면의 빈 공간을 줄이고 세션 구조를 짧게 보여주도록 했다.
- `처음부터` 버튼을 넓은 주 행동으로 바꾸고, `질문폰 보기`, `설정`, `종료`를 하단 보조 행동으로 정리했다.
- `종료` 버튼 색을 패널 배경과 구분되도록 조정했다.
- 질문 칩과 장면 핫스팟의 `보여주나요`식 표현을 `어떤 의미인가요`, `무엇이 떠오르나요`처럼 직접 묻는 문장으로 바꿨다.
- 페르소나 데이터의 visible reply fields에서 `정리됨`, `언급`, `전시`, `프로그램`, `UI`, 별표 강조 같은 금지 표현이 남지 않도록 점검하고 수정했다.

## 3차 검토 회의

- 기억장은 주제가 열렸다는 사실만 보여주어, 플레이어가 어떤 질문을 던졌는지에 따른 차이가 약했다.
- 마무리 카드의 `오늘 열린 장면`도 일반 설명 위주라 세션마다 다른 기록물처럼 느껴지는 힘이 부족했다.
- 5달러 이상 판매를 가정하면 대화형 게임의 보상은 단순 진행도보다 `내가 나눈 대화가 남았다`는 감각이 중요하다고 판단했다.
- 그래서 기억장 카드와 마무리 기록에 실제 질문의 짧은 흔적을 남기고, 저장/이어하기에서도 그 흔적이 복원되도록 하기로 했다.

## 3차 반영 내역

- 질문에 답변을 받을 때마다 열린 기억장 주제에 `물음: ...` 형태의 짧은 세션 노트를 저장하도록 했다.
- 기억장 카드가 일반 설명만 보여주지 않고, 해당 장면을 열게 한 질문의 흔적을 함께 보여주도록 했다.
- 마무리 카드의 `오늘 열린 장면`과 로컬 저장 기록에도 기억장 노트가 포함되도록 했다.
- 자동 저장 데이터에 기억장 노트를 포함해, 이어하기 후에도 세션별 흔적이 유지되도록 했다.

## 4차 검토 회의

- 기억장에 장면이 저장되더라도 상단 상태 문구만 바뀌면 사용자가 보상을 놓치기 쉽다.
- 판매용 대화 게임이라면 큰 이펙트보다 짧고 절제된 피드백으로 `방금 새 장면이 남았다`는 감각을 주는 편이 낫다.
- 기억장 버튼 자체가 다음 행동의 위치이므로, 새 장면이 열릴 때 버튼 근처에 짧은 알림을 띄우고 버튼을 가볍게 강조하기로 했다.

## 4차 반영 내역

- 새 기억장 주제가 열릴 때 `새 장면: 주제` 알림이 기억장 버튼 근처에 잠깐 나타나도록 했다.
- 해금 순간 기억장 버튼이 짧게 펄스되어 다음에 눌러볼 위치를 알려주도록 했다.
- 처음부터 다시 시작할 때 해금 알림과 버튼 펄스가 남지 않도록 초기화했다.

## 5차 검토 회의

- 마무리 기록을 텍스트 파일로 저장하는 것만으로는 판매용 게임의 수집 보상처럼 느끼기 어렵다.
- 플레이어가 저장한 문장을 앱 안에서 다시 열람할 수 있어야 한 세션이 끝난 뒤에도 결과물이 남는 감각이 생긴다.
- 기록 폴더 열기는 보조 기능으로 남기되, 타이틀과 설정에서 접근 가능한 `기록함`을 추가해 최근 마무리 기록을 바로 읽을 수 있게 하기로 했다.

## 5차 반영 내역

- 타이틀 화면과 설정 메뉴에 `기록함` 진입 버튼을 추가했다.
- 저장된 마무리 기록 파일을 읽어 최근 기록 목록과 미리보기로 보여주는 기록함 오버레이를 추가했다.
- 기록함에서 새로고침, 폴더 열기, 닫기 동작을 지원하도록 했다.
- 마무리 기록을 저장한 뒤 기록함이 열려 있으면 목록과 미리보기가 바로 갱신되도록 했다.

## 6차 검토 회의

- 현재 앱은 화면 반응은 늘었지만 사운드 피드백이 없어 버튼, 기억장 해금, 기록 저장 같은 행동이 조용히 지나간다.
- 판매용 대화 게임은 과한 효과음보다 짧고 낮은 사운드가 조작감을 만든다.
- 별도 음원 의존도를 늘리지 않고, 앱 내부에서 짧은 UI 톤과 낮은 방 분위기음을 생성해 패키징 부담을 줄이기로 했다.

## 6차 반영 내역

- 버튼 클릭, 질문폰/기억장/기록함 열기, 기억장 해금, 마무리 기록 저장에 짧은 사운드 피드백을 추가했다.
- 앱 실행 중 낮게 깔리는 방 분위기음을 추가했다.
- 설정 메뉴에서 `소리 기본`, `소리 작게`, `소리 끔`을 순환 선택할 수 있게 하고 선택값을 저장하도록 했다.

## 7차 검토 회의

- 기억장은 수집 결과를 잘 보여주지만, 질문을 고르는 순간에는 어떤 주제를 이미 열었는지 알기 어렵다.
- 판매용 대화 게임에서는 다음 행동을 플레이어가 계속 추측하게 두기보다, 진행 상태를 질문 선택 화면 안에서 바로 보여주는 편이 좋다.
- 질문폰을 단순 질문 목록이 아니라 작은 진행판으로 바꾸고, 이미 열린 주제는 완료 상태로 표시하기로 했다.

## 7차 반영 내역

- 질문폰 상단에 `장면 n/6` 진행 표시를 추가했다.
- 질문폰의 주제 버튼이 열린 장면이면 `완료` 문구와 강조 색으로 바뀌도록 했다.
- 기억장 수집, 이어하기, 처음부터 다시 시작 흐름에서 질문폰 진행 표시가 함께 갱신되도록 했다.

## 8차 검토 회의

- 기록함을 만들었지만 저장 파일 자체는 선택한 문장과 열린 장면 중심이라, 실제로 어떤 대화를 나눴는지 되짚기 어렵다.
- 5달러 이상 판매를 가정하면 한 세션이 끝난 뒤 남는 기록물은 플레이어의 문답 과정을 함께 담아야 한다.
- 마무리 기록에 세션 요약과 전체 대화 로그를 plain text로 추가해, 기록함에서 다시 열었을 때 그날의 흐름이 읽히도록 하기로 했다.

## 8차 반영 내역

- 마무리 기록에 문답 수와 열린 장면 수를 포함한 `세션 요약`을 추가했다.
- 마무리 기록 하단에 `오늘의 대화` 섹션을 추가해 실제 문답 로그가 함께 저장되도록 했다.
- Unity 화면용 색상/굵기 태그는 저장 파일에 남지 않도록 plain text 변환을 거치게 했다.

## 9차 검토 회의

- 기록함 목록이 시간만 보여주면 기록이 여러 개 쌓였을 때 어떤 세션인지 고르기 어렵다.
- 판매용 컬렉션 화면이라면 목록 단계에서 최소한의 의미 단서가 보여야 한다.
- 각 기록 슬롯에 저장 시각과 `오늘 남길 문장`의 앞부분을 함께 보여주기로 했다.

## 9차 반영 내역

- 기록함 목록 버튼이 저장 시각 아래에 선택한 마무리 문장 일부를 함께 표시하도록 했다.
- 오래된 기록 파일이나 읽기 실패 파일은 기존처럼 날짜만 보여주도록 예외 처리를 유지했다.
- 두 줄 표시에서도 버튼 안 글자가 깨지지 않도록 줄 간격과 최소 글자 크기를 조정했다.

## 10차 검토 회의

- 여섯 장면을 모두 열어도 기억장 카운트만 6/6이 될 뿐, 플레이어에게 완성했다는 별도 보상이 약하다.
- 5달러 이상 판매를 가정하면 수집을 끝낸 순간에는 과한 연출보다 분명한 완성 신호와 다음 행동 안내가 필요하다.
- 마지막 장면 해금 순간, 기억장, 마무리 카드, 저장 기록이 모두 `전체 장면 완성` 상태를 공유하도록 하기로 했다.

## 10차 반영 내역

- 여섯 번째 장면이 열리면 `모든 장면 완성` 알림과 확인 사운드가 나오도록 했다.
- 기억장 하단에 완성 배지를 추가해 남은 장면 수 또는 모든 장면 완성 상태를 보여주도록 했다.
- 모든 장면을 연 상태에서는 마무리 카드 요약과 저장 기록에 완성 상태가 드러나도록 했다.

## 11차 검토 회의

- `처음부터`와 타이틀의 `질문폰 보기`가 저장된 이어하기 데이터를 즉시 지워, 실수 클릭의 손실이 크다.
- 판매용 게임에서는 저장 삭제나 진행 초기화처럼 되돌리기 어려운 행동에 확인 단계를 둬야 한다.
- 기록함의 마무리 기록은 남기되, 현재 이어하기 데이터와 진행 중 기억장이 지워진다는 점을 명확히 알려주기로 했다.

## 11차 반영 내역

- 타이틀의 `처음부터`, `질문폰 보기`, 일시정지의 `처음부터`가 진행 데이터가 있을 때 확인 팝업을 띄우도록 했다.
- 확인 팝업에는 지워지는 항목과 남는 기록함 데이터를 구분해 안내했다.
- 첫 실행처럼 버릴 진행이 없을 때는 확인 없이 바로 시작되도록 했다.
- ESC로 확인 팝업을 닫을 수 있게 했다.

## 12차 검토 회의

- 질문폰에는 여섯 장면이 모두 보이지만, 답변 직후 떠 있는 추천 질문은 서버 추천이나 이전 기본 질문에 머물 수 있다.
- 판매용 대화 게임에서는 플레이어가 같은 주제에 갇히지 않고 남은 장면을 자연스럽게 열도록 다음 행동이 안내되어야 한다.
- 답변 직후 추천 질문은 아직 열리지 않은 기억장 주제를 우선 섞고, 서버가 준 문장은 보조 추천으로 다듬어 사용하기로 했다.

## 12차 반영 내역

- 답변 후 추천 질문 3개 중 앞쪽에 아직 열리지 않은 기억장 주제 질문이 우선 배치되도록 했다.
- 서버 추천 문장에 줄바꿈이나 별표 강조가 섞여도 버튼에는 짧은 질문 문장으로 정리되게 했다.
- 여섯 장면을 모두 열면 추천 문구가 남은 장면 안내가 아니라 자유 질문 안내로 바뀌도록 했다.

## 13차 검토 회의

- 이어하기 버튼은 활성화되지만, 플레이어가 어떤 세션으로 돌아가는지 첫 화면에서 알 수 없다.
- 판매용 게임에서는 저장 데이터가 있다는 사실뿐 아니라 현재 질문 진행도와 수집 상황이 보여야 재방문 신뢰가 생긴다.
- 타이틀의 짧은 흐름 영역을 저장 요약과 겸용해, 새 대화와 이어하기 상태가 같은 자리에서 읽히게 하기로 했다.

## 13차 반영 내역

- 타이틀 화면의 흐름 영역이 저장된 대화가 있을 때 `지난 대화`, 질문 진행도, 기억장 진행도, 마지막 장면을 보여주도록 했다.
- 저장 데이터가 없을 때는 기존처럼 `오늘의 흐름`과 세션 단계를 보여주도록 유지했다.
- 저장 JSON이 깨졌거나 비어 있으면 이어하기 버튼이 활성화되지 않도록 저장 상태 판정을 실제 저장 구조 기준으로 바꿨다.

## 14차 검토 회의

- 마무리 카드는 기록을 저장할 수 있지만, 저장 직후 플레이어가 저장 결과를 확인하려면 직접 기록함을 찾아야 한다.
- 판매용 게임에서 엔딩 직후의 만족감은 파일이 만들어졌다는 상태 문구보다, 방금 만든 기록물이 바로 눈앞에 열리는 흐름에서 더 잘 생긴다.
- 기록 저장 버튼을 저장과 확인을 함께 하는 행동으로 바꾸고, 저장된 기록을 기록함에서 즉시 선택해 보여주기로 했다.

## 14차 반영 내역

- 마무리 카드의 `기록 저장` 버튼을 `저장 후 보기`로 바꿨다.
- 기록 저장이 성공하면 기록함을 자동으로 열고 최신 저장 기록을 바로 선택하도록 했다.
- 같은 초에 여러 번 저장해도 파일명이 겹치지 않도록 저장 파일명에 밀리초를 포함했다.

## 15차 검토 회의

- 앱 내부 품질은 올라갔지만, 유료 배포물은 실행 파일만으로 평가되지 않는다.
- 로컬 서버, API 모델 설정, Node.js 유무, API 실패 시 동작이 문서와 실제 코드에서 서로 맞아야 한다.
- 서버/API가 실패해도 텍스트 대화가 끊기지 않게 하고, 배포 전 확인 항목을 별도 체크리스트로 분리하기로 했다.

## 15차 반영 내역

- 릴리즈 전 QA를 스크립트화해, 문서에 적힌 기준이 실제 명령으로 재현되게 만들기로 했다.

- 유료 게임 기준에서는 사물 단서를 눌렀을 때 질문 내용을 먼저 확인하고, 플레이어가 의도적으로 `묻기`를 선택해야 조작감이 안정된다.
- 이 확인 흐름은 마우스뿐 아니라 키보드 Enter/Esc로도 닫거나 확정할 수 있어야 한다.

## 57차 반영 내역

- 사물 핫스팟 클릭 시 바로 질문하지 않고 `책상 단서` 확인 쪽지를 먼저 띄우도록 바꿨다.
- 확인 쪽지에는 질문 문장과 `묻기`, `닫기` 버튼을 제공하고, Enter로 확정, Esc로 취소할 수 있게 했다.
- 질문폰이나 새 세션을 열 때 남아 있던 핫스팟 확인 쪽지는 자동으로 닫히게 했다.
- 릴리즈 스모크에 `hotspot-preview.png` 캡처를 추가하고 접근성 자동 QA가 이 캡처를 확인하도록 했다.

## 58차 검토

- 접근성 자동 QA는 `panel-shortcut-*.tsv` 보고서의 PASS/FAIL을 읽어 실제 런타임 상태 기준으로 통과 여부를 판단한다.

## 65차 반영 내역

- 서버의 답변 정리 경로를 강화해 `좋아요`, `물론이죠`, `잠깐`, `잠시만요`, `네` 같은 접수 표현과 `저는 실제 사람이 아니라...`, `가상책`, `AI`식 정체성 문구가 답변 첫머리에 남지 않게 했다.
- Unity에서도 서버 답변을 표시, 저장, 기억장 수집 전에 한 번 더 정리해 API 응답이 흔들려도 게임 안에는 같은 기준이 적용되게 했다.
- 서버 추천 질문도 줄바꿈, 별표 강조, 접수 표현을 제거하고 중복 없이 3개까지 정리하도록 했다.
- `RunContentQA.ps1`, `RunLongSessionQA.ps1`, `RunSafetyQA.ps1`가 답변 본문과 추천 질문 전체에서 마크다운 흔적, AI식 표현, 제작자용 표현, 과한 길이를 검사하도록 강화했다.

## 검수 기준

- 질문 입력 직후 하단 대사창에는 짧은 생각 중 문장만 나온다.
- 답변 첫머리에 `저는 실제 사람이 아니라...` 문장이 반복되지 않는다.
- 답변에 별표 강조가 남지 않는다.
- 답변과 추천 질문에는 `좋아요`, `물론이죠`, `잠깐`, `가상책`, `AI`, `프로그램`, `UI` 같은 몰입을 깨는 표현이 남지 않아야 한다.
- 추천 질문과 답변이 관람자에게 말하는 문장으로 보인다.
- 캐릭터가 찌그러져 보이지 않고 보라색 경계가 눈에 띄지 않는다.
- 새 배경이 밝고, 조사실 같은 느낌이 줄어든다.
- 빌드 실행 후 스모크 캡처에서 패널, 캐릭터, 배경, 긴 대사창이 겹치지 않는다.
- 진행 표시는 0/5에서 시작해 질문마다 채워지고, 5문답 이후 마무리 가능 상태로 바뀐다.
- 마무리 카드는 화면 중앙에 떠야 하며 대사창, 질문폰, 캐릭터와 incoherent하게 겹치지 않아야 한다.
- 마무리 카드에는 현재 세션에서 열린 기억장 장면이 요약되어야 하며, 열린 장면이 없을 때도 빈 상태 문장이 깨지지 않아야 한다.
- 마무리 기록 저장은 선택한 문장과 열린 장면 요약을 파일로 남겨야 하고, 저장 실패 시 앱이 멈추지 않아야 한다.
- 첫 실행에서는 타이틀 화면이 먼저 보여야 하고, 시작 후에는 바로 질문과 대화가 가능해야 한다.
- ESC 일시정지 화면은 현재 화면 위에 뜨며 계속하기와 처음부터 흐름이 동작해야 한다.
- 질문 후 기억장 카운트가 올라가고, 기억장에는 수집한 장면만 설명 문장으로 열려야 한다.
- 기억장, 마무리 카드, 일시정지 화면은 ESC로 닫히거나 전환되어야 하며 서로 시각적으로 충돌하지 않아야 한다.
- 상단 상태 문구는 `기억장`, `질문폰` 버튼 뒤로 새거나 겹쳐 보이지 않아야 한다.
- 대사 글자 크기를 키워도 긴 답변은 대사창 안에서 스크롤되어야 하며, 하단 입력줄이나 진행 표시를 밀어내지 않아야 한다.
- 설정 메뉴는 타이틀과 일시정지 화면 위에서 열리고 닫혀야 하며, 글자 크기 선택과 화면 모드 변경이 저장되어야 한다.
- 정보 화면은 앱의 자료 기반과 개인정보/API 키 저장 정책을 짧게 안내해야 하며, 기록 폴더 버튼은 저장 디렉터리를 만들고 열어야 한다.
- 정보 화면은 로컬 서버 연결과 API 키 유무를 짧게 표시하고, 서버가 없어도 UI가 멈추지 않아야 한다.
- 타이틀 화면은 시작 행동, 질문폰, 설정, 종료가 한눈에 구분되어야 하고 버튼 대비가 패널 배경에 묻히지 않아야 한다.
- 타이틀 화면의 흐름 표시는 긴 기능 설명이 아니라 짧은 세션 흐름으로 읽혀야 하며, 본편 UI와 겹쳐 보이지 않아야 한다.
- 기억장에는 열린 주제뿐 아니라 그 주제를 열게 한 질문의 짧은 흔적이 보여야 한다.
- 마무리 카드와 저장 기록의 `오늘 열린 장면`에는 기억장 노트가 함께 남아야 한다.
- 이어하기 후에도 기억장 노트가 사라지지 않아야 한다.
- 새 기억장 주제가 열리면 해금 알림이 짧게 보이고, 다른 패널이나 입력줄을 가리지 않아야 한다.
- 처음부터 다시 시작하면 해금 알림과 기억장 버튼 강조가 남아 있지 않아야 한다.
- 기록함은 타이틀 화면과 설정 메뉴에서 열려야 하고, 최근 저장 기록 목록과 선택한 기록의 본문을 함께 보여야 한다.
- 기록함에 저장된 파일이 없을 때는 빈 상태 문장이 보여야 하며, 저장 후에는 새로고침 없이도 최신 기록을 읽을 수 있어야 한다.
- 기록함 목록은 날짜만이 아니라 저장한 마무리 문장의 앞부분도 함께 보여야 한다.
- 마무리 기록 파일에는 세션 요약, 오늘 남길 문장, 오늘 열린 장면, 오늘의 대화가 함께 들어가야 한다.
- 여섯 장면을 모두 열면 완성 알림, 기억장 완성 배지, 마무리 카드의 완성 문구가 보여야 한다.

- 타이틀 화면에 저장된 대화가 있으면 질문 진행도, 기억장 진행도, 마지막 장면이 짧게 보여야 한다.

## 66차 반영 내역

### 회의 판단

- 자동 QA, 외부 증거 감사, 플레이테스트 요약, 외부 이슈 레지스터, 상업 출시 결정이 각각 따로 존재해 최종 출시 버튼 직전 한 번에 확인하는 운영 흐름이 약했다.
- 5달러 이상 유료 판매 후보라면 개별 보고서가 모두 있어도 최종 게이트가 보류인지 차단인지 한눈에 드러나야 한다.
- 외부 증거가 없는 상태를 성공처럼 보이게 하지 않으면서, 현재 로컬에서 가능한 자동 감사는 계속 통과 여부를 증거로 남기기로 했다.

- API 키 검사는 강해야 하지만 Unity 실행 파일, DLL, 이미지, 영상까지 단순 문자열 검색하면 바이너리 내부의 임의 바이트가 키처럼 보이는 오탐이 생길 수 있다.
- 오탐 때문에 패키지 검증이 멈추면 실제 보안 위험과 검증 도구 문제를 구분하기 어려워진다.
- 상업 출시 후보 검증은 텍스트 파일에서는 키 흔적을 엄격히 잡고, 바이너리는 필수 파일 존재와 매니페스트 검증으로 관리하는 편이 더 정확하다.

### 개발 반영

- Windows 배포 패키지, Steam 제출 패키지, Steamworks 스테이징 패키지, 외부 플레이테스트 패키지, 상업 검토 패키지 검증에 텍스트성 파일 필터를 추가했다.
- 외부 증거 감사, 플레이테스트 증거 요약, 외부 증거 세션 수집의 비밀키 검색도 텍스트성 파일만 대상으로 하도록 맞췄다.
- README, 문서, JSON, TSV, PowerShell, 배치, VDF, 자막, 설정 파일, 로그 등 운영자가 직접 열어보는 텍스트 파일은 계속 API 키 패턴 검사를 받는다.
- 릴리즈 감사의 소스 보안 검색은 오래된 `Build` 산출물 스냅샷을 제외하고, 현재 패키지는 전용 validator 결과로 판정하도록 정리했다.
- 릴리즈 감사의 비밀키 검색 결과는 매칭된 줄 내용을 보고서에 복사하지 않고, 생성 보고서의 과거 실패 문구가 다음 검색을 다시 실패시키지 않도록 했다.

### 검수 기준

- 같은 배포 패키지에서 `UnityPlayer.dll` 같은 바이너리 오탐 때문에 보안 검증이 실패하지 않아야 한다.
- 오래된 `Build` 하위 패키지 스냅샷에 과거 placeholder가 남아 있어도 현재 릴리즈 감사의 소스 보안 검색을 실패시키지 않아야 한다.
- 한 번 실패한 릴리즈 감사 보고서가 키 형태 문자열을 자기 안에 품고 다음 실행까지 연쇄 실패시키지 않아야 한다.
- 텍스트성 패키지 파일에 API 키 형태 문자열이 있으면 기존처럼 즉시 실패해야 한다.
- 릴리즈 감사와 상업 출시 게이트는 자동 QA 실패 없이 실행되고, 남은 보류 사유는 실제 외부 검증 증거 부족으로만 남아야 한다.

### 검수 기준

- 외부 플레이테스트 패키지와 상업 검토 패키지는 새 export 도구를 포함하고, 패키지 검증을 통과해야 한다.

## 84차 반영 내역

### 회의 판단

### 개발 반영

- `Tools/WriteInternalCommercialReview.ps1`를 추가해 릴리즈 감사, 외부 증거 감사, 플레이테스트 요약, 품질 루브릭 QA, 최종 게이트 보고서를 읽고 내부 상업 리뷰를 생성하도록 했다.
- `Docs/INTERNAL_COMMERCIAL_REVIEW.md`와 `Docs/INTERNAL_COMMERCIAL_BACKLOG.tsv`를 생성해 프로듀서, QA, 접근성 검토자, 아트 리뷰어, 트레일러 편집자, 상점 운영자 기준의 다음 행동을 기록한다.
- 현재 상태에서는 자동 QA와 상점 제출 자료는 준비됐지만, 외부 플레이테스트, 실제 접근성 QA, 외부 아트 리뷰, 최종 트레일러, Steam 관리자/법무 증거, 5달러 품질 점수표가 P1 백로그로 남도록 했다.

- Windows 배포 패키지, 상업 검토 패키지, Steam 제출 패키지에 내부 상업 리뷰와 백로그를 포함하고, 패키지 validator가 누락을 잡도록 했다.

### 검수 기준

- 내부 상업 리뷰는 자동 QA 통과/실패, 외부 증거 미완료 수, 플레이테스트 완성 세션, 품질 루브릭 상태, 최종 게이트 상태를 한 화면에 보여야 한다.

- Windows 배포 패키지, 상업 검토 패키지, Steam 제출 패키지는 내부 상업 리뷰와 백로그를 포함해야 한다.

## 85차 반영 내역

- 외부 플레이테스트 패키지와 상업 검토 패키지는 새 도구와 증거 수집 계획 파일을 포함하고, validator가 누락을 잡도록 했다.

### 검수 기준

- 템플릿, 참고 파일, 생성 보고서, 리뷰 브리프는 실제 증거로 수입하지 않도록 제외했다.
- 같은 파일은 건너뛰고, 대상에 다른 내용의 파일이 있으면 `-Force` 없이는 충돌로 멈추도록 했다.
- `Tools/ValidateExternalEvidenceImport.ps1`와 `Docs/EXTERNAL_EVIDENCE_IMPORT_QA.md`를 추가해 수입 보고서 상태, 충돌 0, 비밀키 0을 검증한다.
- Windows 배포 패키지, 외부 플레이테스트 패키지, Steam 제출 패키지, 상업 검토 패키지에 수입 QA와 도구가 포함되도록 연결했다.

### 검수 기준

- 빈 템플릿 중심의 `EvidenceDrop`을 미리보기 수입해도 실제 증거로 복사 대상으로 잡히면 안 된다.
- 반환 패키지의 실제 증거는 허용된 영역만 원본 증거 폴더로 들어가야 한다.
- 충돌 파일은 `-Force` 없이는 복사되지 않아야 한다.
- 수입 보고서에 충돌 또는 비밀키 형태 문자열이 있으면 QA가 실패해야 한다.

## 93차 반영 내역

### 회의 판단

- 추적 보드와 브리프가 있어도 실제 전달 시점에는 리뷰어별로 무엇을 보내야 하는지 다시 묶어야 한다.
- 외부 플레이테스트 5명과 접근성, 아트, 트레일러, Steam/법무, 품질점수표, 이슈 폐쇄는 각기 다른 증거 위치와 완료 기준을 갖는다.

### 개발 반영

- `Tools/WriteExternalReviewerPackets.ps1`를 추가해 `Build/ReleaseEvidence/ReviewerPackets`에 11개 리뷰 항목별 전달 패킷을 생성하도록 했다.
- 각 패킷에는 `README.md`, `INVITE.txt`, `ACCEPTANCE_CHECKLIST.tsv`, `SOURCE_BRIEF.md`가 들어간다.
- `Tools/ValidateExternalReviewerPackets.ps1`와 `Docs/EXTERNAL_REVIEWER_PACKETS_QA.md`를 추가해 필수 패킷, 체크리스트 항목, 비밀키 형태 문자열, 별표 강조 여부를 검증한다.
- `PrepareCommercialEvidenceWorkspace.ps1`가 증거 작업공간을 만들 때 리뷰어 패킷까지 함께 준비하도록 연결했다.
- Windows 배포 패키지, 외부 플레이테스트 패키지, Steam 제출 패키지, 상업 검토 패키지에 리뷰어 패킷 문서와 도구가 포함되도록 생성/검증 스크립트를 갱신했다.
- `ImportExternalEvidenceDrop.ps1`가 `ReviewerPackets`를 실제 증거로 수입하지 않도록 제외했다.

### 검수 기준

- 리뷰어 패킷은 추적 TSV의 11개 항목과 1대1로 대응해야 한다.
- 각 패킷에는 초대문, 리뷰어 README, 원본 브리프, 수락 체크리스트가 있어야 한다.
- 패킷은 실제 증거로 세지 않아야 하며, 반환 EvidenceDrop 수입에서도 제외되어야 한다.
- 패키지 검증은 리뷰어 패킷 문서, QA 보고서, 패키지 안의 `EvidenceDrop/ReviewerPackets`가 누락되면 실패해야 한다.

## 94차 반영 내역

### 회의 판단

- 패키지 검증 규칙이 추가된 직후에는 기존 패키지들이 낡은 상태라 첫 재생성 중 릴리스 리포트가 일시적으로 실패할 수 있다.
- 이 실패가 생성 스크립트를 중단시키면 새 규칙을 만족하는 패키지를 만들 수 없어, 검증 규칙 변경 후의 부트스트랩 순서가 막힌다.
- 최종 게이트는 계속 엄격해야 하지만, 패키지 생성 도중의 스냅샷 실패는 경고로 남기고 모든 패키지를 다시 만들 수 있어야 한다.

### 개발 반영

- `Tools/MakeReleasePackage.ps1`, `Tools/MakeExternalPlaytestPackage.ps1`, `Tools/MakeCommercialReviewPackage.ps1`, `Tools/MakeSteamSubmissionPackage.ps1`에서 릴리스 준비 리포트 스냅샷 생성 실패를 경고로 처리하도록 했다.
- 각 패키지 생성 스크립트는 경고가 있어도 최신 `RELEASE_READINESS_REPORT.md`를 복사하고 manifest를 다시 쓰도록 유지했다.
- 외부 플레이테스트, 상업 리뷰, Steam 제출, Windows 릴리스 패키지를 순서대로 재생성해 새 리뷰어 패킷 요구사항을 모두 포함시켰다.
- 최종 `WriteReleaseReadinessReport.ps1`와 `RunCommercialLaunchGate.ps1`는 별도로 다시 실행해 자동 실패와 차단 게이트가 0인지 확인했다.

### 검수 기준

- 패키지 생성 도중 다른 패키지가 낡아 생기는 릴리스 스냅샷 실패는 경고로만 남아야 한다.
- 개별 패키지 검증 스크립트는 최신 산출물 기준으로 모두 통과해야 한다.
- 최종 릴리스 준비 리포트는 자동 실패 0, 외부 검증 미완료 5를 유지해야 한다.
- 상업 출시 게이트는 최종 판정 보류, 차단 0을 유지해야 한다.
