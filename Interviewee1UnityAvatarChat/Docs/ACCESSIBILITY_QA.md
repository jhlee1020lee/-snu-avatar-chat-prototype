# 접근성 QA 메모

`겉!=속`를 유료 배포 후보로 볼 때 확인해야 할 접근성 기준이다.

## 키보드 조작 기준

마우스를 쓰지 않아도 주요 흐름에 접근할 수 있어야 한다.

| 입력 | 기대 동작 |
| --- | --- |
| `Enter` | 직접 묻기 입력칸에서 현재 질문 전송 |
| `Shift+Enter` | 직접 묻기 입력칸에서 줄바꿈 유지 |
| `Esc` | 열린 패널 닫기, 닫을 패널이 없으면 일시정지 |
| `1`, `2`, `3` | 기본 화면에서는 현재 추천 질문 1~3번 선택, 질문 노트가 열려 있으면 `질문`, `장면`, `기록` 탭 선택 |
| `←`, `→` | 질문 노트가 열려 있을 때 탭 이동 |
| `Q` | 질문 노트 열기/닫기 |
| `M` | 기억장 열기/닫기 |
| `R` | 기록함 열기/닫기 |
| `S` | 설정 열기/닫기 |
| `I` | 정보 열기/닫기 |
| `F` | 전체 화면 전환 |
| `+`, `-` | 대사 글자 크기 키우기/줄이기 |
| `↑`, `↓` | 대사창 또는 기록함 읽기 위치 조금 이동 |
| `PageUp`, `PageDown` | 대사창 또는 기록함 읽기 위치 크게 이동 |
| `Home`, `End` | 대사창 또는 기록함 처음/끝으로 이동 |

패널이 열린 상태에서는 현재 패널의 닫기 단축키만 우선 동작한다. 예를 들어 기록함이 열려 있으면 `R`은 기록함을 닫고, `Q`, `M`, `S`, `I`는 뒤쪽 화면의 다른 패널을 열지 않는다. `F`, `+`, `-`는 화면 조정용으로 계속 사용할 수 있다.

## 게임패드 기본 조작 기준

게임패드가 연결된 환경에서는 키보드 단축키와 같은 핵심 흐름에 접근할 수 있어야 한다.

| 입력 | 기대 동작 |
| --- | --- |
| `A` | 첫 화면에서 인터뷰 시작, 단서 미리보기에서 묻기 확정 |
| `B` | 열린 패널 닫기, 닫을 패널이 없으면 일시정지 |
| `X` | 질문 노트 열기 |
| `Y` | 기억장 열기 |
| `LB`, `RB` | 질문 노트 탭 이동, 기본 화면에서는 글자 크기 줄이기/키우기 |
| `Back` | 기록함 열기 |
| `Menu` | 설정 열기 |

## 화면 읽기 전 점검

- 긴 답변은 하단 대사창에서 한 번에 밀려 나오지 않고, 클릭 또는 `PageDown`으로 다음 대사처럼 넘겨 읽을 수 있어야 한다.
- 기록함 미리보기는 키보드만으로 위아래 읽기 이동이 가능해야 한다.
- 패널이 열린 상태에서 다른 패널 단축키를 눌러도 화면 뒤쪽에 새 패널이 겹쳐 열리지 않아야 한다.
- 게임패드 `A`로 현재 추천 질문을 진행하고, `X/Y/Back/Menu`로 질문 노트, 기억장, 기록함, 설정을 열고 `B`로 닫을 수 있어야 한다.
- 기본 화면에서는 `LB/RB`로 추천 질문을 바꾸고, 질문 노트가 열려 있을 때는 `LB/RB`로 탭을 이동할 수 있어야 한다.
- 설정 화면에서는 `LB/RB`로 글자 크기 조정을 확인할 수 있어야 한다.
- 큰 글자 설정에서도 입력줄, 진행 표시, 하단 대사창이 서로 겹치지 않아야 한다.
- 설정 화면의 글자 크기, 소리, 화면 모드, 움직임 줄임 버튼은 1920x1080에서 겹치지 않아야 한다.
- 움직임 줄임을 켜면 아바타와 핫스팟의 반복 움직임이 줄어들어야 한다.
- 소리를 꺼도 질문, 기록 저장, 삭제, 이어하기는 그대로 동작해야 한다.
- `Tools/ValidateAccessibilityAutomation.ps1`로 키보드 단축키 코드와 접근성 관련 스모크 캡처가 준비됐는지 먼저 확인한다.
- 릴리즈 스모크가 생성한 `panel-shortcut-*.tsv` 보고서에 `FAIL`이 없어야 하며, 열린 패널이 다른 단축키로 뒤섞이지 않았다는 `PASS` 항목이 있어야 한다.
- 자동 QA 결과는 `Docs/ACCESSIBILITY_AUTOMATION_QA.md`에 남긴다.
- 자동 QA는 실제 스크린리더, 고대비, 화면 확대, 보조 입력 장치 테스트를 대체하지 않는다.

## 실제 보조기기 QA에서 확인할 것

- Windows 고대비 모드에서 텍스트가 읽히는지 확인한다.
- 키보드만 사용해 시작, 질문 선택, 기억장 확인, 마무리 카드 저장, 기록함 확인까지 진행한다.
- 화면 확대 125%, 150% 환경에서 대사창과 설정 패널이 화면 밖으로 밀리지 않는지 확인한다.
- 실제 참가자가 길게 읽는 상황에서 글자 크기와 다음 대사 넘김 조작이 충분한지 기록한다.
- `ACCESSIBILITY_OBSERVATION_FORM.md`에 실제 환경, 입력 장치, 문제 화면, 판정을 남긴다.

## 통과 기준

- 키보드만으로 5문답 이상 진행하고 마무리 기록을 저장할 수 있다.
- 큰 글자와 움직임 줄임을 켠 상태에서도 주요 패널이 겹치지 않는다.
- 실제 보조기기 테스트에서 진행 불가 이슈가 없어야 한다.
