# 겉!=속 개선 실행 보고서

- 작성일: 2026-06-04
- 기준 문서: `Docs/GAME_IMPROVEMENT_REVIEW_20260604.md`
- 대상 프로젝트: `Interviewee1UnityAvatarChat`
- 작성 목적: Claude 리뷰의 지적을 실제 개발 작업으로 바꾸기 위한 우선순위, 구현 방향, 검증 기준 정리

## 결론

현재 `겉!=속`은 인터뷰 답변, 안전장치, 접근성은 강하지만 플레이어가 "내 선택으로 겉 단서가 속 생활로 이어졌다"는 감각을 충분히 받기 어렵다. 따라서 당장 중요한 개선은 새 시스템을 크게 추가하는 것이 아니라, 이미 코드에 들어 있는 첫인상, 질문 태도, 깊은 기록, 마무리 카드 정보를 플레이 흐름의 중심으로 끌어올리는 것이다.

개선 순서는 다음이 가장 현실적이다.

1. 첫 1분 온보딩을 명확하게 만든다.
2. 마무리 카드가 플레이어의 선택 경로를 되짚게 만든다.
3. 깊은 기록 해금 조건과 피드백을 더 게임 규칙처럼 보이게 만든다.
4. 이후 연출과 코드 구조를 단계적으로 정리한다.

## 현재 상태 근거

- `Assets/Scripts/AvatarChatApp.cs`는 현재 14,445줄이며, UI 생성, 상태 관리, 대화 흐름, 저장, 테스트 코드가 한 파일에 모여 있다.
- `Assets/Scenes/AvatarChat.unity`는 약 4.8KB 수준의 씬 파일이고, 별도 프리팹은 현재 확인되지 않는다.
- 첫인상, 깊은 기록, 마무리 카드와 관련된 핵심 재료는 이미 존재한다.
  - `firstImpression`, `lastQuestionAttitude`, `deepMemoryUnlocked`
  - `ShouldUnlockDeepMemory(...)`
  - `BuildFirstImpressionArcLine()`
  - `UpdateClosingSummary()`
  - `BuildChoiceConsequenceLine(...)`
- 서버 쪽은 `Interviewee1CloneAI/server.js`, `data/persona.json` 기반으로 답변 품질과 안전 범위가 비교적 잘 잡혀 있다.

## 유지해야 할 강점

### 답변 톤과 윤리 경계

답변은 담백하고 조심스럽다. 이 장점은 유지해야 한다. 개선 과정에서 게임성을 높이더라도, 인터뷰이를 극복담의 주인공처럼 만들거나 감정 연출을 과장하면 프로젝트의 핵심 의도와 충돌한다.

유지 기준:

- 게임명은 `겉!=속` 유지
- 확인되지 않은 병명, 회사명, 학교명, 가족사, 개인 취향 추가 금지
- 본인 재현이 아니라 인터뷰 기반 전시 대화라는 경계 유지
- 도움, 이동, 자취, 책상, 취미를 한 사람의 생활 맥락으로 연결

### 서버 필수 흐름

사용자가 요청한 "서버가 정상이 아니면 실행이 안되게" 방향은 유지해야 한다. 서버 필수 모드는 신뢰성과 테스트 전달 측면에서 중요하다.

유지 기준:

- 시작 버튼은 서버 정상 확인 전 비활성 또는 차단
- 서버 오류 문구는 사용자가 할 일을 알 수 있게 짧게 표시
- 로컬 폴백은 개발/비상용으로만 남기고, 플레이테스트 기본 흐름은 서버 필수로 고정

## 개선안 1. 첫 1분 온보딩 재구성

### 판단

Claude 리뷰의 P0 지적에 동의한다. 현재 첫 화면은 배경, 아바타, 제목, 설명, 설정/정보, 이어하기/처음부터/질문 노트/이야기 보기 등 여러 기능이 동시에 보인다. 처음 보는 사람에게는 "무엇을 해야 하는 게임인지"보다 "버튼이 많은 화면"으로 읽힐 가능성이 높다.

### 개선 목표

첫 화면에서 플레이어가 다음 세 가지를 즉시 이해해야 한다.

- 목표: 겉으로 먼저 보이는 단서를 고르고, 질문으로 그 뒤의 생활을 확인한다.
- 첫 행동: 먼저 눈에 들어온 장면 하나를 고른다.
- 완료 조건: 5번 묻고 나면 마무리 카드에서 내가 연 경로를 확인한다.

### 구현 방향

`CreateStartMenuOverlay(...)`와 시작 화면 문구를 중심으로 수정한다.

권장 화면 구조:

1. 제목: `겉!=속`
2. 목표 문장: `먼저 보이는 단서를 고르고, 5번의 질문으로 그 뒤의 생활을 열어 보세요.`
3. 첫 행동 문장: `처음에는 정답을 맞히지 않습니다. 지금 눈에 들어온 장면 하나를 고르면 됩니다.`
4. 완료 조건 문장: `5문답 후 마무리 카드에서 내가 고른 겉 단서와 열린 속 장면을 확인합니다.`
5. 주요 버튼: `처음부터`
6. 보조 버튼: `이어하기`, `설정`, `정보`

`질문 노트`, `이야기 보기`는 첫 화면에서 같은 무게로 노출하지 않는 것이 좋다. 둘 다 초보자에게는 별도 모드처럼 보인다. 필요하면 `처음부터` 이후 흐름 안에서 자연스럽게 열리게 한다.

### 구체 작업

- 시작 화면 버튼 우선순위 재배치
  - `처음부터`를 가장 눈에 띄는 기본 행동으로 둔다.
  - `이어하기`는 저장 데이터가 있을 때만 첫 번째 보조 행동으로 둔다.
  - `질문 노트`, `이야기 보기`는 첫 화면의 주 버튼에서 제외하거나 설명이 붙은 보조 영역으로 낮춘다.
- `BuildStartObjectiveLine()` 계열 문구가 있다면 목표/첫 행동/완료 조건을 분리한다.
- 서버 확인 상태 문구를 시작 흐름과 같은 영역에 배치한다.
  - 예: `서버 연결 확인 중입니다. 연결되면 시작할 수 있습니다.`
  - 예: `서버 연결 필요: 시작 파일로 서버를 먼저 켜 주세요.`

### 검증 기준

- 새 플레이어가 첫 화면에서 5초 안에 첫 행동을 말할 수 있어야 한다.
- 화면에 같은 위계의 시작 버튼이 3개 이상 보이지 않아야 한다.
- 설정/정보는 눈에 띄되, 시작 행동보다 강하지 않아야 한다.
- 서버가 꺼져 있으면 시작할 수 없고 이유가 보인다.

## 개선안 2. `겉!=속` 선택 경로를 마무리 카드의 중심으로 만들기

### 판단

현재 코드에는 이미 `BuildFirstImpressionArcLine()`과 `UpdateClosingSummary()`가 있고, 마무리 카드에 첫인상과 깊은 기록 수가 들어간다. 하지만 리뷰 지적처럼 플레이어가 "내 선택 때문에 이 결말이 나왔다"라고 강하게 느끼기에는 부족하다. 정보가 존재하지만 게임의 핵심 보상처럼 보이지 않는다.

### 개선 목표

마무리 카드는 단순한 종료 팝업이 아니라 플레이 결과 화면이어야 한다. 플레이어가 다음 문장을 볼 수 있어야 한다.

`처음 본 것: 목발 → 열린 속 장면: 이동/도움/일과 공부 → 깊어진 질문 태도: 배려/호기심 → 남길 문장`

### 구현 방향

`UpdateClosingSummary()`를 결과 화면의 핵심 영역으로 강화한다. 현재 요약은 여러 줄 텍스트에 가깝기 때문에, 플레이어가 시각적으로 경로를 읽을 수 있는 구조로 바꾼다.

권장 표시:

- `처음 본 겉 단서`
  - 목발 / 책상 / 표정 / 첫인상 없이 시작
- `이어진 속 장면`
  - 열린 장면 목록과 깊음/얕음 상태
- `내 질문 태도`
  - 단정 / 배려 / 호기심 / 거리두기 중 주된 태도
- `겉!=속 경로`
  - `처음 본 목발이 이동 깊은 기록까지 이어졌습니다.`
- `다음에 더 물어볼 장면`
  - 아직 얕거나 열리지 않은 장면 하나

### 구체 작업

- `UpdateClosingSummary()`의 문구를 결과 카드형 정보로 정리한다.
- `BuildFirstImpressionArcLine()`을 짧고 강한 결과 문장으로 조정한다.
- `BuildOpenedSceneTags(...)`는 최대 3개만 보여주되, 나머지는 `외 N개`로 정리한다.
- 선택한 마무리 태그가 왜 추천되는지 현재보다 더 눈에 띄게 표시한다.
- 마무리 카드 버튼 이름을 더 결과 중심으로 바꾼다.
  - `저장 후 보기` → `기록함에 저장`
  - `계속하기` → `질문 더 하기`

### 검증 기준

- 첫인상을 고른 세션과 고르지 않은 세션의 마무리 카드 문구가 다르게 보여야 한다.
- 깊은 기록이 0개인 경우와 1개 이상인 경우의 결과 문구가 달라야 한다.
- 플레이어가 마무리 카드만 보고 오늘 어떤 경로를 밟았는지 설명할 수 있어야 한다.

## 개선안 3. 깊은 기록 해금 조건을 "규칙"처럼 보이게 만들기

### 판단

현재 `ShouldUnlockDeepMemory(theme, question, attitude)`는 이미 특정 태도와 질문 내용이 맞을 때 깊은 기록을 여는 구조다. 즉 시스템은 있다. 문제는 플레이어가 그 규칙을 충분히 인지하지 못한다는 점이다.

### 개선 목표

깊은 기록은 우연히 찍히는 체크가 아니라, 플레이어가 좋은 질문을 해서 얻는 결과처럼 느껴져야 한다.

### 구현 방향

현재 조건을 완전히 어렵게 만들기보다, 조건과 피드백을 명확하게 만든다.

권장 규칙:

- 장면을 여는 질문: 어떤 주제든 물어보면 해당 장면이 열린다.
- 깊은 기록을 여는 질문: `배려` 또는 `호기심` 태도이면서, 해당 장면의 속 생활을 구체적으로 묻는다.
- 단정 질문: 답변은 받을 수 있지만 깊은 기록은 잘 열리지 않는다.

### 구체 작업

- 질문 노트 상단에 규칙 문장 추가
  - `장면은 질문으로 열리고, 깊은 기록은 배려/호기심 질문으로 열립니다.`
- 추천 질문 카드에 태도 힌트를 더 명확히 표시
  - `배려 질문`
  - `호기심 질문`
  - `단정에 가까움`
- 깊은 기록이 열렸을 때 토스트를 더 결과 중심으로 표시
  - 현재: `새 기록: 도움 깊은 기록 열림`
  - 개선: `깊은 기록 열림: 도움을 먼저 묻는 방식까지 확인했습니다.`
- 얕은 기록일 때도 다음 행동을 알려준다.
  - `이 장면은 열렸습니다. "어떻게/왜/무엇이 편한가요"처럼 물으면 깊어집니다.`

### 검증 기준

- 같은 장면에서 단정 질문과 배려/호기심 질문의 결과 피드백이 구분되어야 한다.
- 플레이어가 기록함에서 `열림`, `깊음`, `더 묻기` 상태 차이를 이해할 수 있어야 한다.
- 깊은 기록 해금이 너무 빡빡해져 5문답 안에 1개도 못 여는 일이 흔해지면 안 된다.

## 개선안 4. 감정 곡선과 연출 강화

### 판단

답변이 안전하고 담백한 것은 강점이다. 따라서 감정 곡선을 만든다고 해서 극적인 사건이나 과장된 음악을 넣으면 안 된다. 필요한 것은 드라마가 아니라 호흡이다.

### 개선 목표

플레이어가 "텍스트를 읽었다"보다 "한 사람의 하루를 따라갔다"는 느낌을 받게 한다.

### 구현 방향

이미 이야기 모드에는 정적, 시선, 조명 같은 연출 큐가 있다. 이 큐를 텍스트로만 두지 말고 실제 화면 변화에 연결한다.

권장 연출:

- 첫인상 선택 직후: 선택한 단서 쪽으로 카메라/조명/포커스 이동
- 깊은 기록 해금: 작은 소리, 카드 하이라이트, 아바타 표정 변화
- 단정 질문 후: 즉시 반박보다 잠깐의 정적과 조심스러운 답변
- 배려/호기심 질문 후: 답변 전개가 조금 더 열리는 느낌
- 마무리 카드: 오늘 열린 장면을 조용히 되짚는 화면

### 구체 작업

- `ApplyStoryModeSceneDirection(...)` 계열 로직이 있다면 실제 카메라/조명/아바타 표정과 더 직접 연결한다.
- `currentStoryModePaceLine`은 내부 상태나 QA용 텍스트가 아니라 실제 타이밍 조절 값으로 활용한다.
- 깊은 기록 해금 토스트에만 의존하지 말고 기록함 카드 자체가 잠깐 강조되게 한다.
- 사운드는 과하게 쓰지 말고 방 톤, 페이지 넘김, 짧은 확인음 정도로 제한한다.

### 검증 기준

- 이야기 모드에서 장면이 넘어갈 때 화면 변화가 있어야 한다.
- 깊은 기록 해금 시 플레이어가 별도 설명 없이도 "뭔가 열렸다"고 느껴야 한다.
- 연출이 답변 윤리를 해치거나 동정심을 과장하지 않아야 한다.

## 개선안 5. 코드 구조 정리

### 판단

코드 구조 지적은 맞지만, 당장 대규모 구조 개편을 먼저 하면 위험하다. 지금은 플레이테스트 가능성이 더 중요하므로 기능 흐름을 먼저 개선하고, 구조 정리는 단계적으로 해야 한다.

### 개선 목표

단일 파일의 위험을 줄이고, UI 수정과 문구 수정이 서로 영향을 덜 주게 만든다.

### 1단계: 낮은 위험 정리

- `AvatarChatApp.cs`를 기능별 `partial class`로 분리
  - `AvatarChatApp.StartMenu.cs`
  - `AvatarChatApp.FirstImpression.cs`
  - `AvatarChatApp.QuestionNote.cs`
  - `AvatarChatApp.MemoryBook.cs`
  - `AvatarChatApp.ClosingCard.cs`
  - `AvatarChatApp.Server.cs`
  - `AvatarChatApp.SmokeTests.cs`
- 색상, 폰트, 간격 상수 묶기
  - `AvatarChatTheme.cs` 또는 같은 partial 내부의 테마 영역
- 사용자 표시 문구를 별도 영역으로 모으기
  - 이전에 정리한 `USER_VISIBLE_KOREAN_TEXT_FOR_CLAUDE.md`를 기준으로 우선순위 높은 문구부터 코드에서 찾기 쉽게 정리

### 2단계: 중간 위험 정리

- 반복되는 `Stretch(...)`, `CreateText(...)`, `CreateButton(...)` 패턴을 화면별 헬퍼로 줄인다.
- 고정 픽셀 오프셋이 많은 영역부터 anchors와 레이아웃 그룹으로 옮긴다.
- 시작 화면, 마무리 카드, 질문 노트처럼 사용자가 오래 보는 UI부터 우선 정리한다.

### 3단계: 높은 위험 정리

- Unity 프리팹화
- Canvas 레이아웃 시스템 전면 적용
- 코드 생성 UI에서 디자이너 캔버스 기반 UI로 이전

이 단계는 플레이테스트 전보다는 후속 안정화 작업으로 잡는 것이 낫다.

### 검증 기준

- partial 분리 후 Unity 컴파일이 깨지지 않아야 한다.
- 기능별 파일을 열었을 때 해당 화면의 문구와 레이아웃을 찾을 수 있어야 한다.
- 구조 정리 커밋은 UI 동작 변경과 분리하는 것이 좋다.
