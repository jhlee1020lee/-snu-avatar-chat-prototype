# 플레이테스트 진행자 스크립트

외부 참가자 세션에서 진행자가 읽고 체크할 수 있는 스크립트입니다. 목표는 게임을 설명으로 끌고 가지 않고, 처음 보는 사람이 어디서 이해하고 어디서 막히는지 확인하는 것입니다.

## 시작 전 준비

- 참가자 코드를 정한다. 이름, 전화번호, 계정 정보는 관찰 양식에 적지 않는다.
- 실행 패키지의 빌드 ID를 관찰 양식에 적는다.
- `Forms/PLAYTEST_OBSERVATION_FORM.md`를 참가자 코드로 복사해 채운다.
- 화면 녹화나 음성 녹음을 할 경우 별도 동의 절차를 먼저 마친다.
- 테스트 PC에 API 키, Steam 계정 비밀번호, 개인 인증 정보가 화면에 보이지 않는지 확인한다.

## 참가자에게 읽을 안내

오늘은 `겉!=속`라는 대화형 게임을 테스트합니다.

제가 먼저 조작법을 자세히 설명하지는 않습니다. 처음 보는 플레이어가 무엇을 이해하고 어디서 막히는지 보려는 테스트입니다. 게임 실력을 평가하는 자리가 아니고, 막히는 지점이 있으면 그 자체가 중요한 결과입니다.

최소 다섯 번 이상 질문과 답변을 진행해 주세요. 답변이 길면 끝까지 읽어 보고, 불편하거나 어색한 부분이 있으면 말로 알려 주세요. 마지막에는 저장, 기록, 의견 남기기까지 확인합니다.

개인정보, 실제 비밀번호, 계정, 민감한 건강 정보는 입력하지 마세요. 테스트 중 남는 피드백과 지원 자료는 문제 확인과 수정에만 사용합니다.

## 진행 중 개입 기준

개입하지 않는 경우:

- 참가자가 첫 행동을 고민한다.
- 질문폰, 직접 입력, 기억장, 기록함을 스스로 찾으려 한다.
- 긴 답변을 읽다가 다음 대사 넘김을 알아차리는지 본다.
- 말투가 이상하다고 혼잣말하거나 반응한다.

짧게 개입하는 경우:

- 2분 이상 아무 조작도 하지 못한다.
- 앱 진행이 멈춘 것으로 보인다.
- 참가자가 개인정보나 계정 정보를 입력하려 한다.
- 화면 녹화나 저장 위치에 대해 불안해한다.

개입 문장:

- 지금 느낀 대로 해 보시면 됩니다.
- 막힌 부분을 말로 설명해 주세요.
- 개인정보는 입력하지 말고 가상의 예시로 바꿔 주세요.
- 지금 화면에서 찾을 수 있는 단서만으로 진행해 보겠습니다.

## 관찰 중 반드시 기록할 항목

- 첫 질문까지 걸린 시간
- 직접 질문을 입력했는지 여부
- 긴 답변을 끝까지 읽었는지 여부
- 긴 답변에서 다음 대사 넘김을 알아차렸는지 여부
- 기억장과 마무리 카드의 의미를 이해했는지 여부
- 저장 기록과 삭제 안내를 신뢰했는지 여부
- 사람 말처럼 들리지 않은 문장이나 반복 어투
- 돈을 내고 하기에는 부족하다고 느낀 점

## 세션 종료 질문

1. 이 게임이 어떤 경험이라고 느껴졌나요?
2. 가장 좋았던 순간은 무엇이었나요?
3. 가장 불편하거나 어색했던 순간은 무엇이었나요?
4. 답변 길이와 다음 대사 넘김은 읽기 편했나요?
5. 사람에게 듣는 느낌과 설명문을 읽는 느낌 중 어느 쪽에 가까웠나요?
6. 저장 기록과 삭제 안내를 믿을 수 있었나요?
7. 돈을 내고 플레이한다면 망설이게 할 이유는 무엇인가요?

## 세션 후 처리

1. 참가자가 앱 안에서 의견을 남겼는지 확인한다.
2. `PlaytestFeedback` 폴더의 텍스트와 JSON 파일을 확인한다.
3. 지원 번들을 생성한다.
4. 관찰 양식, 피드백 원문, 피드백 JSON, 지원 번들을 한 세션 폴더에 묶는다.
5. 발견한 문제는 `RegisterExternalIssue.ps1`로 등록한다.
6. `RUN_EVIDENCE_AUDIT.bat`를 실행해 증거 상태를 갱신한다.

## 실패로 보는 세션

- 5문답에 도달하지 못했고 원인이 기록되지 않았다.
- 관찰 양식, 피드백 원문, 피드백 JSON, 지원 번들 중 하나가 없다.
- 참가자 개인정보나 계정 정보가 증거 폴더에 남았다.
- 진행자가 과도하게 설명해서 첫 1분 이해도를 판단할 수 없다.
